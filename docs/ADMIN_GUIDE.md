# Инструкция администратора

Документ покрывает раздел 6 ТЗ: управление товарами, категориями, заказами,
пользователями, отзывами, промокодами и контентом.

> **Статус.** Админ-панель реализуется на этапе 6. Документ описывает целевой
> сценарий и будет дополнен скриншотами по мере готовности разделов.
> До этого момента каталог наполняется сид-данными: `docker compose exec backend python -m app.cli seed`.

## 1. Вход в панель

| Роль | Разделы | Раздел ТЗ |
|---|---|---|
| Менеджер | заказы, клиенты, комментарии, трек-номера | 3.3 |
| Администратор | всё, включая товары, роли, контент, статистику | 3.4 |

Админка живёт по адресу `/admin` — это подраздел витрины с отдельной оболочкой
и ленивой загрузкой чанков, поэтому не утяжеляет бандл покупателя.

Учётные записи создаёт `app/cli.py` (`create-admin`) — пароль в панели никогда
не отображается, только хеш (раздел 6.4 ТЗ).

## 2. Товары

Раздел 6.1 ТЗ. Поля товара и их смысл:

| Поле | Примечание |
|---|---|
| название, slug | slug — человекочитаемый URL, менять после публикации нежелательно |
| артикул (SKU) | уникальный ключ, участвует в импорте и поиске |
| бренд, категория | задают набор доступных фильтров |
| цена, старая цена | старая цена показывается только если больше текущей |
| закупочная цена | видна только администратору, не выводится в API витрины |
| остаток, зарезервированный остаток, минимальный остаток | доступно = остаток − резерв |
| статус | «в наличии», «мало на складе», «под заказ», «ожидается поставка», «отсутствует», «снят с продажи» |
| гарантия (месяцев) | выводится на карточке товара |
| характеристики | набор задаётся справочником категории |
| изображения | главное помечается флагом, остальные сортируются вручную |
| вес и габариты | нужны для расчёта доставки |
| SEO Title / Description | переопределяют значения, сгенерированные из товара |

## 3. Категории

Раздел 6.1. Вложенность — через `parent_id`, максимальная глубина — два уровня
(«Комплектующие → Процессоры»). Для каждой категории задаётся набор
характеристик из справочника: именно он определяет фильтры и колонки сравнения
в каталоге.

## 4. Заказы

Раздел 6.3.

### Статусы

```
Новый → Подтверждён → Ожидает оплаты → Оплачен → Собирается
      → Передан в доставку → Готов к выдаче → Выполнен

Любой активный статус → Отменен
Оплачен / Выполнен   → Возврат → Возвращён
```

Переходы вне этой схемы система отклоняет с кодом `409`.

### Действия в карточке заказа

- смена статуса — с фиксацией в журнале `admin_audit_log`;
- комментарий для клиента;
- трек-номер;
- просмотр данных клиента и состава заказа;
- печать заказа;
- отмена — возврат резерва в свободный остаток;
- оформление возврата.

Цены и названия товаров в заказе хранятся отдельно от карточки: изменение
товара не переписывает уже оформленные заказы (критерий приёмки №25).

## 5. Пользователи

Раздел 6.4. Поиск по email, телефону и имени. Действия: блокировка, смена роли,
сброс пароля, просмотр истории заказов. Пароли не отображаются никогда.

## 6. Отзывы

Раздел 5.12. Пользователь может оставить отзыв только на товар из
завершённого заказа. Модерация: скрыть, удалить, отклонить, отметить
как проверенный при покупке.

## 7. Промокоды

Раздел 6.5. Типы скидок: фиксированная сумма, процент, бесплатная доставка.
Ограничения: минимальная сумма заказа, максимальный размер скидки, срок действия,
лимит использований, лимит на пользователя, список категорий и исключённых
товаров.

## 8. Контент

Раздел 6.6. Редактируются баннеры, акции, страницы «О компании», «Доставка»,
«Оплата», «Гарантия», «Возврат», FAQ, контакты и ссылки на соцсети.

## 9. Импорт товаров

Раздел 14. Загрузка CSV или XLSX. Обязательные поля: артикул, название,
категория, бренд, цена, старая цена, количество, описание, гарантия, изображение.

Процесс: проверка формата → проверка обязательных полей → проверка уникальности
артикулов → проверка существования категорий и брендов → проверка цен и
количеств → предварительный отчёт → импорт корректных строк → отчёт по ошибкам.

## 10. Статистика

Раздел 6.4: выручка, количество заказов, средний чек, самые продаваемые
товары, товары с низким остатком, динамика заказов по дням.

## 11. Безопасность при работе с панелью

- все действия администраторов пишутся в журнал (раздел 10 ТЗ);
- пароль в панели не отображается и не редактируется напрямую — только сброс;
- доступ к панели выдаётся по роли, проверка — на backend;
- смена роли другого администратора требует подтверждения.
